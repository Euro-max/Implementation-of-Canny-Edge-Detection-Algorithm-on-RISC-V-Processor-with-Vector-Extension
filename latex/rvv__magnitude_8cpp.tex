RVV-\/accelerated L1 gradient magnitude with two-\/pass normalisation. 

\hypertarget{rvv__magnitude_8cpp_autotoc_md9}{}\doxysubsubsection{\texorpdfstring{Algorithm recap (matching scalar baseline in magnitude.\+cpp)}{Algorithm recap (matching scalar baseline in magnitude.cpp)}}\label{rvv__magnitude_8cpp_autotoc_md9}
{\bfseries{Pass 1}} — for every pixel i\+: {\ttfamily temp\mbox{[}i\mbox{]} = \texorpdfstring{$\vert$}{|}\+Gx\mbox{[}i\mbox{]}\texorpdfstring{$\vert$}{|} + \texorpdfstring{$\vert$}{|}\+Gy\mbox{[}i\mbox{]}\texorpdfstring{$\vert$}{|}} (int32\+\_\+t, maximum value ≈ 2×32 767 = 65 534) Track the running maximum across the whole image.

{\bfseries{Pass 2}} — normalise to \mbox{[}0, 255\mbox{]}\+: {\ttfamily output\mbox{[}i\mbox{]} = (uint8\+\_\+t)(temp\mbox{[}i\mbox{]} \texorpdfstring{$\ast$}{*} 255 / max\+\_\+mag)}\hypertarget{rvv__magnitude_8cpp_autotoc_md10}{}\doxysubsubsection{\texorpdfstring{Why this is a good RVV candidate}{Why this is a good RVV candidate}}\label{rvv__magnitude_8cpp_autotoc_md10}

\begin{DoxyItemize}
\item Pass 1 is purely element-\/wise on the SoA Gx/\+Gy arrays — a perfect fit for strip-\/mined vector abs + add.
\item The running max across the image requires a {\bfseries{vector reduction}} at the end of each strip\+: {\ttfamily vredmax} folds a vector of N elements into a single scalar.
\item Pass 2 multiplies every temp value by the same scalar (255/max\+\_\+mag) — another broadcast-\/scalar × vector pattern.
\item No boundary conditions at all — this is a flat 1-\/D loop over W×H elements.
\end{DoxyItemize}\hypertarget{rvv__magnitude_8cpp_autotoc_md11}{}\doxysubsubsection{\texorpdfstring{New RVV concept\+: vector reduction}{New RVV concept: vector reduction}}\label{rvv__magnitude_8cpp_autotoc_md11}

Gx and Gy are int16\+\_\+t. After abs and add the result is int32\+\_\+t (to avoid overflow\+: max \texorpdfstring{$\vert$}{|}\+Gx\texorpdfstring{$\vert$}{|}+\texorpdfstring{$\vert$}{|}\+Gy\texorpdfstring{$\vert$}{|} is 65 534, fits in int16\+\_\+t actually, but we keep int32\+\_\+t to match the scalar baseline and avoid signed-\/overflow UB).

For widening int16→int32 we use LMUL=m2 for the int16 load, giving m4 for the int32 accumulation. This lets us process more elements per iteration (at VLEN=256, m2 holds 32 int16 elements → 512 bits).
