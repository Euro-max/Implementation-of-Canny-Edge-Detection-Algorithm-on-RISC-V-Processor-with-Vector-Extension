\hypertarget{md_PHASE5__README_autotoc_md7}{}\doxysection{\texorpdfstring{How The Timing Works}{How The Timing Works}}\label{md_PHASE5__README_autotoc_md7}
We use the RISC-\/V {\ttfamily rdcycle} hardware instruction — reads the CPU cycle counter before and after each stage, subtracts to get elapsed cycles. Each stage runs {\bfseries{100 times}} and we average to eliminate noise from QEMU.


\begin{DoxyCode}{0}

\DoxyCodeLine{\ \ \ \ uint64\_t\ c;}

\DoxyCodeLine{\ \ \ \ \textcolor{keywordflow}{return}\ c;}
\DoxyCodeLine{\}}
\DoxyCodeLine{}
\DoxyCodeLine{\textcolor{comment}{//\ Usage:}}
\DoxyCodeLine{c0\ =\ read\_cycles();}
\DoxyCodeLine{\textcolor{keywordflow}{for}\ (\textcolor{keywordtype}{int}\ i\ =\ 0;\ i\ <\ 100;\ i++)}
\DoxyCodeLine{\ \ \ \ gaussian\_blur\_5x5(...);}
\DoxyCodeLine{c1\ =\ read\_cycles();}
\DoxyCodeLine{uint64\_t\ avg\ =\ (c1\ -\/\ c0)\ /\ 100;}

\end{DoxyCode}


\begin{quote}
{\bfseries{Why not clock\+\_\+gettime?}} Our bare-\/metal toolchain (riscv64-\/unknown-\/elf) has conflicts between time.\+h and C++ headers. {\ttfamily rdcycle} needs zero headers and works everywhere. \end{quote}
\begin{quote}
{\bfseries{Why 100 repetitions?}} QEMU runs on your host OS alongside other processes. A single measurement might catch an OS interrupt and read 20\% too high. 100 runs averaged is stable within 1-\/2\%. \end{quote}

\hypertarget{md_PHASE5__README_autotoc_md15}{}\doxysubsection{\texorpdfstring{Sobel\+: 70.\+5x speedup (\+O0 → O3)}{Sobel: 70.5x speedup (O0 → O3)}}\label{md_PHASE5__README_autotoc_md15}
The compiler {\bfseries{auto-\/vectorized}} Sobel at {\ttfamily -\/O3}. The Sobel inner loop is simple and branchless, so GCC rewrote it using SIMD instructions automatically. This is why Sobel went from 56\% of total time at O0 down to only 9.\+6\% at O3.\hypertarget{md_PHASE5__README_autotoc_md16}{}\doxysubsection{\texorpdfstring{Gaussian\+: only 6.\+6x speedup}{Gaussian: only 6.6x speedup}}\label{md_PHASE5__README_autotoc_md16}
The Gaussian inner loop has a boundary check\+: 
\begin{DoxyCode}{0}
\DoxyCodeLine{\textcolor{keywordflow}{if}\ (img\_y\ <\ 0\ ||\ img\_y\ >=\ height\ ||\ img\_x\ <\ 0\ ||\ img\_x\ >=\ width)}
\DoxyCodeLine{\ \ \ \ \textcolor{keywordflow}{continue};\ \ \textcolor{comment}{//\ zero\ padding}}

\end{DoxyCode}
 This {\ttfamily if} statement inside the loop {\bfseries{prevents auto-\/vectorization}} — the compiler cannot process multiple pixels in parallel if different pixels take different code paths. This is exactly why we need RVV intrinsics in Phase 7.\hypertarget{md_PHASE5__README_autotoc_md17}{}\doxysubsection{\texorpdfstring{Magnitude\+: 5.\+7x speedup}{Magnitude: 5.7x speedup}}\label{md_PHASE5__README_autotoc_md17}
Two-\/pass structure (find max, then normalize) creates a data dependency between passes. The compiler can\textquotesingle{}t vectorize across passes. Also a target for Phase 7.\hypertarget{md_PHASE5__README_autotoc_md18}{}\doxysubsection{\texorpdfstring{Direction\+: 2.\+2x speedup}{Direction: 2.2x speedup}}\label{md_PHASE5__README_autotoc_md18}
Already fast enough. Not worth optimizing further (see Amdahl\textquotesingle{}s Law below).

\hypertarget{md_PHASE5__README_autotoc_md22}{}\doxysection{\texorpdfstring{Important Limitation to Mention in Report}{Important Limitation to Mention in Report}}\label{md_PHASE5__README_autotoc_md22}
\begin{quote}
QEMU does not simulate real hardware cycles. It does not model cache misses, pipeline stalls, or branch misprediction. The {\bfseries{absolute numbers}} (e.\+g. "{}33\+M cycles"{}) are not what a real RISC-\/V chip would produce. However, the {\bfseries{relative ratios}} (O0 vs O3 = 12x, scalar vs RVV later) are valid because the instruction count genuinely changes between optimization levels. \end{quote}
